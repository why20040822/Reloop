## 一、需求演进史（5 轮转向，先钉住避免再偏）

| 轮次 | 你的表述 | 理解的方向 | 结果 |
|---|---|---|---|
| v0 | 扩展里加撞库组件，不影响其他功能 | 浏览器扩展新增独立组件 | ✅ MatchPlus/TalentLens v1 |
| v1 | 抓取页面逻辑点，不要写 URL；整体架构；缺失点 | 网络捕获层 + 五层架构 | ✅ v4.8.10 网络捕获版 |
| v2 | 悬浮层重构、无 TTC 痕迹、验证后上线 | 中性品牌 + 测试 + 打包 | ✅ 人才速查 TalentLens |
| v3 | 去掉自动入库，只留信息匹配 | 拦截原插件 3 个写接口 | ✅ 双层拦截上线 |
| v4 | "Reloop 网站内嵌撞库，展示 TTC 全部备注" → 修正为 "看 Reloop 信息时展示公司人才库补充" | **最终方向：Reloop 详情页内嵌公司库补充** | ✅ company-supplement 上线 |
| v5 | 补充信息能拉 PDF 简历吗 | CRM 私域库 PDF 调研 | ❌ 被卡（见 R7），降级方案① resume_text 已上线 |

**最终需求主线的准确表述**：
> 在 Reloop 网站看人才信息时，内嵌展示公司人才库（TTC）的最新补充信息（备注/状态/差异）与简历内容；浏览器扩展在招聘网站侧做撞库入口（查 TTC 私域库 + 信息匹配），并拦截自动入库。

## 三、架构现状 vs 目标

```
【现状】（两套已交付、互不相通的系统）

  猎聘/直聘/脉脉/领英 页面
   └─ TalentLens 扩展组件
       ├─ 网络捕获身份 ──► 查 TTC 私域库 ──► 抽屉展示（命中/私库标注/投递状态/跳转）
       └─ 拦截自动入库（3 写接口）
                              ┌──────── 公司共享池(TTC) ────────┐
                              │  实时快照(30min TTL)             │
  Reloop 网站(yorkteam.cn) ◄──┤                                  │
   └─ 人才详情页               └────────────────────────────────┘
       ├─ 公司人才库补充卡片（差异高亮）
       └─ 简历文本卡片（resume_text）

【目标态缺口】（把两套系统接起来的三座桥）

  桥A: 扩展撞库时同步查 Reloop 库 → 展示 Reloop 备注/互动      (R13, 需扩展鉴权)
  桥B: Reloop 加"粘贴候选人→撞库"入口                          (R10, lookup.py 已备好)
  桥C: PDF 简历链路                                            (R7, 等 TTC 修 search)
```

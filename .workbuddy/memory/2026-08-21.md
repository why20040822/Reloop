## 去 TTC Token 粘贴页 + 飞书登录隔离（方案已锁定，待实现）
- **需求**：去掉 settings 里的 TTC Token 粘贴/绑定页（Brainx 已有扫码鉴权，Reloop 飞书扫码登录即等价），改为按飞书登录用户做数据隔离。
- **已锁定决策**：(1) 隔离模型=**严格按登录用户**(每飞书用户只看到自己的人才+工件)；(2) 同步凭证=**服务端全局 .env TTC Token**(`BRAINX_TTC_TALENT_AUTH_TOKEN`，所有同步走它，用户只消费隔离视图)。
- **现状隐患**：`deps.get_current_user` 在 X-Auth-Token 失败时回退到 `X-Owner-User-Id` 直接当隔离键 → 生产可被伪造越权；`auth_auto_register=True` 自动建用户。存量 368 talent(+5298 recommendation) owner=`ou_ff894386...`(TTC open_id，非 fs_ 飞书用户)，去绑定后成孤儿。
- **实施清单(本地改, 生产部署另确认)**：
  1. config.py 加 `auth_require_token: bool = True`(prod 默认开; dev 本地设 False 以便 X-Owner 调试)。
  2. deps.py：auth_require_token=True 时必须 X-Auth-Token，否则 401；关闭 X-Owner 伪造回退(dev 才放开)；auth_auto_register 生产 False。
  3. auth.py 删 `POST /auth/ttc/bind` + decode_ttc_jwt_unverified 用途；/me 保留(ttc_bound 字段可弃用)。
  4. sync.py `/sync/ttc` 只用全局 token(用户 ttc_auth_token 保持 None 即回落全局，无需大改)。
  5. webapp/app.js renderSettings 删"账号/私域人才库"卡片(token/space/bind/sync UI+handler)。
  6. models.py `ttc_auth_token` 列弃用(留着不删，避免 DB migration)。
  7. **生产数据再归属(待确认)**：把 `ou_ff894386...` 的 talent/recommendation 等改挂到 Mia 的飞书 fs_ open_id(先让她登录读 /auth/me 拿 id，或查 users 表 display_name 含 Mia/钟笑咪)。

# Playbooks · AI 作战手册库

> 把「AI 干一类活的标准流程」固化成单个 Markdown 文件。
> 比 skill 重（有变量、验收、避坑），比系统轻（没有代码，一个文件就是全部）。

## 给小白的一分钟上手

1. 打开你要用的那个 `.md` 文件（比如 `feishu-personal-manual.md`）
2. **只改「✍️ 定制区」的表格**，其他一律不动，保存
3. 对你的 AI（Claude Code / Codex / OpenCode 均可）说：

   ```
   请严格按照 @feishu-personal-manual.md 为我执行，定制区我已经填好。
   每步完成后按验收清单自查，失败了按兜底方案处理，处理不了停下来问我。
   ```

4. AI 跑完后，你对照「✅ 验收清单」逐项确认。

**前提**： playbook 里写了需要的工具（如 lark-cli、Chrome），你的电脑得先装好并登录。
没装就把 playbook 发给 AI 说「先帮我做前置检查」，它会告诉你缺什么。

## 文件结构规范（六个固定区，顺序不变）

| 区 | 谁看 | 内容 |
|---|---|---|
| Frontmatter | 机器/人 | name、version、owner、tools、risk、更新日期 |
| ① 用途 | 人 | 一句话说清干什么、产出什么 |
| ② ✍️ 定制区 | **人（只改这里）** | 变量表格：`{{变量名}}`、说明、示例值 |
| ③ 📦 模板区 | 人（少改） | 内容模板，变量用 `{{变量名}}` 占位 |
| ④ 🤖 执行区 | AI | 编号步骤，每步含：命令/操作 → 预期结果 → 失败兜底 |
| ⑤ ✅ 验收清单 | 人 | 可逐项打钩的客观标准 |
| ⑥ 🕳 避坑记录 | 所有人 | 已踩过的坑，**每次执行发现新坑必须补进来** |

## 写作纪律

- 文件名 = kebab-case，一个 playbook 只干一类事
- 变量统一 `{{大写蛇形}}`，定制区里出现的变量必须在模板/步骤中用到，不许有孤儿变量
- 执行区步骤要**确定性强**：写死命令、参数、判断标准，少给 AI 自由发挥空间
- 高风险操作（改权限、发消息、删东西）必须标注 ⚠️ 并要求 AI 执行前向人确认
- 改内容升 version，并在文末记一行变更日志
